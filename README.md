# Шлюз Modbus RTU ↔ TCP

Утилита-шлюз: принимает запросы Modbus RTU от мастера (HMI, SCADA) на COM-порту
и переадресует их устройству по Modbus TCP. Ответ устройства возвращается
мастеру по RTU. Мастер работает с устройством так, будто оно подключено
по последовательной линии.

## Принцип работы

```
Мастер (HMI) --RS-485/RTU--> [Шлюз] --Ethernet/TCP--> Контроллер
```

- Из RTU-кадра извлекается PDU, оборачивается в MBAP-заголовок и отправляется
  на устройство по TCP. Адрес ведомого RTU становится Unit ID.
- Ответ (PDU) упаковывается обратно в RTU-кадр с CRC16.
- Каждому RTU-запросу соответствует один TCP-запрос; шлюз работает строго
  последовательно и не посылает параллельных запросов к устройству.
- При обрыве TCP соединение восстанавливается автоматически (каждые 3 с).
- Если устройство не ответило за тайм-аут или связь с ним потеряна, мастеру
  возвращается исключение Modbus `0B` (шлюз не отвечает) / `0A`.
- Широковещательные запросы (адрес 0) передаются устройству, ответ мастеру
  не возвращается.

### Приём кадров RTU

Кадр отрезается по ожидаемой длине из заголовка запроса (f01–f06 → 8 байт,
f0F/f10 → 9 + N, f16 → 10, f17 → 13 + N), поэтому мастер может слать запросы
вплотную, без межкадровой паузы 3,5 символа. Пауза используется только как
запасной признак конца кадра для неизвестных функций и обрывков.
Кадры с неверной длиной или CRC отбрасываются с записью в журнал.

## Кэш чтения (f03/f04)

Включается чекбоксом «Кэш чтения f03/f04». Назначение — медленные устройства:
мастер получает ответ мгновенно, а устройство опрашивается в щадящем темпе.

Алгоритм:

- Кэшируются только чтения f03/f04, ключ — ведомый + функция + адрес +
  количество. Время жизни записи — 10 с (фиксировано).
- Записи в кэше нет или она протухла — запрос идёт в TCP синхронно,
  ответ пополняет кэш.
- Свежая запись есть — мастеру сразу отдаётся значение из кэша, а запрос
  на обновление ставится в очередь (дубли не добавляются, максимум 64).
- Очередь обновлений выполняется в фоне, только когда линия RTU свободна,
  по одному запросу, не прерывая текущий обмен. Так данные по одному
  TCP-запросу могут быть прочитаны мастером многократно.
- Кэшируются только корректные ответы (не исключения, длина сошлась).
  Максимум 32 записи, при переполнении вытесняется самая старая.

### Инвалидация записью

Запрос записи регистров (f06/f10) вычищает из кэша все записи,
пересекающиеся с записанным диапазоном. Записанное значение в кэш не
кладётся: у контроллера может быть своя логика на запись, поэтому кэш
пополняется только перечитыванием с устройства. Широковещательная запись
чистит кэш по всем ведомым. Данные фонового TCP-обновления, идущего в момент
записи, в кэше не оседают (обмен завершается до обработки записи, и его
результат вычищается инвалидацией).

## Отрицательный кэш (молчащие регистры)

Если устройство не ответило на запрос чтения за тайм-аут (например, запрос
неопределённых регистров, на которых контроллер «задумывается» навсегда),
запрос запоминается на 10 с. Повторы того же запроса в этот период сразу
получают исключение `!f83 0B`, без обращения к TCP и без секундной блокировки
шлюза. По истечении 10 с устройство опрашивается повторно; успешный ответ
снимает запись. Работает независимо от кэша значений.

## Настройки

Сохраняются автоматически в `ModbusGateway.ini` рядом с exe.

| Параметр | Описание |
|---|---|
| Порт | COM-порт, на котором шлюз слушает мастера |
| Скорость, чётность, биты данных, стоп-биты | Параметры линии RTU |
| IP-адрес, порт | Устройство Modbus TCP (обычно порт 502) |
| Тайм-аут ответа, мс | Ожидание ответа устройства (100–60000) |
| Кэш чтения f03/f04 | Включение кэша значений |
| Вести журнал обмена | Строки журнала в окне; ошибки пишутся всегда |

Журнал дублируется в файл `ModbusGateway.log` рядом с exe (UTF-8).

### Параметр командной строки

`ModbusGateway.exe -autostart` — шлюз запускается сразу после старта
программы (для автозагрузки).

## Формат журнала

```
RX: f03 @100 n2                    запрос мастера: функция, адрес (с 0), количество
TX: f03 [1234, 5678]               ответ устройства: все регистры
TX: f03 [1234, 5678] (кэш 350 мс)  ответ из кэша, возраст записи
КЭШ: обновлён: f03 [1234, 5678]    фоновое обновление кэша
TX: !f83 0B (устройство не отвечает)                    исключение мастеру
TX: !f83 0B (устройство не отвечает) (кэш ошибок 47 мс) из отрицательного кэша
RX: f03 @100 n2 (широковещ.)       широковещательный запрос
RX: ... | 01 03 ...                дамп кадра, если PDU не распознан
```

## Сборка

Delphi 13 (RAD Studio 37.0). Сборка из командной строки:

```
MSBuild ModbusGateway.dproj /t:Rebuild /p:Config=Release /p:Platform=Win64
```

Исходники в UTF-8 с BOM (иначе компилятор ломает кириллицу).

## Тесты

Каталог `test/` — эмуляторы для проверки без железа (нужна пара
виртуальных COM-портов com0com, шлюз на COM19, мастер на COM9):

- `tcp_server.py` — эмулятор устройства Modbus TCP (127.0.0.1:5020),
  задержка ответа 300 мс, регистры 296–297 «молчат» (имитация бага),
  счётчик в первом регистре для контроля свежести данных;
- `rtu_master.py <сценарий>` — эмулятор мастера. Сценарии:
  `all` — полный прогон; `burst` — пачка запросов; `glued` — склеенные кадры;
  `write` — запись f06; `ttl` — истечение TTL кэша; `failcache` —
  отрицательный кэш; `inval` — инвалидация записью; `ranges` — чтение
  диапазонов в случайном порядке; `real`/`stress` — опрос реального
  устройства; `probe` — карта «молчащих» адресов.
